# edgetunnel - نسخه‌ی ایران

یک Cloudflare Worker که پروتکل‌های VLESS / Trojan / Shadowsocks را در لبه‌ی کلادفلر پایان می‌دهد
و ترافیک را به یک بک‌اند proxyIP می‌فرستد. این نسخه برای شرایط فیلترینگ ایران تنظیم شده است:
مسیر خروجی پیش‌فرض، **مجموعه‌ای از proxyIPهای عمومی است که به‌صورت موازی مسابقه می‌گیرند** (نه یک
آدرس تصادفی)، و صفحه‌ی تنظیمات را خودِ worker سرو می‌کند، پس هیچ چیزی از یک سایت متفرقه بارگذاری
نمی‌شود.

تمام فایل‌های این ریپو انگلیسی است و در CI بررسی می‌شود که هیچ کاراکتر چینی به آن وارد نشود.

* بدون سرور، بدون دامنه، بدون هزینه: روی پلن رایگان کلادفلر با آدرس `*.workers.dev` اجرا می‌شود.
* لازم دارید: یک اکانت Cloudflare و یک اکانت GitHub.

بر پایه‌ی [cmliu/edgetunnel](https://github.com/cmliu/edgetunnel) با مجوز GNU GPL-2.0 (فایل `LICENSE`).

## تفاوت‌های این نسخه

| مورد | نسخه‌ی اصلی | این نسخه |
| --- | --- | --- |
| خروجی وقتی `PROXYIP` تنظیم نشده | یک سرور اهدایی تصادفی برای هر درخواست | آدرس پیش‌فرض هر colo **به‌علاوه‌ی** `publicProxyPool` قاطی و همزمان تست می‌شوند؛ حالت fallback مستقیم روشن می‌ماند |
| خروجی وقتی `PROXYIP` تنظیم شده | یک مورد تصادفی انتخاب می‌شود و fallback **خاموش** می‌شود | تمام لیست شما یکسان‌سازی، قاطی و دسته‌ای مسابقه داده می‌شود؛ fallback عمداً خاموش می‌ماند |
| صفحه‌ی تنظیمات | از یک سایت چینیِ بیرونی گرفته می‌شود | داخل خود worker ساخته می‌شود (`/login` و `/admin`)، کاملاً انگلیسی |
| زبان کد | نام‌ها و توضیحات چینی | همه‌چیز انگلیسی؛ CI در صورت دیدن کاراکتر چینی build را رد می‌کند |

رفتار پروتکل، فرمت لینک‌ها، پشتیبانی xHTTP/gRPC و ساختار config در KV تغییر نکرده است — فقط نام
کلیدها انگلیسی شده است.

## راه‌اندازی

1. این ریپو را در GitHub خودت داشته باش (انجام شده).
2. داشبورد کلادفلر <- **Workers & Pages** <- **Create** <- **Deploy from Git**.
   اگر اتصال GitHub را ندیدی، اول از سطح اکانت **Settings -> Git integration** وصلش کن و دسترسی
   را فقط به همین ریپو بده.
3. همین ریپو را انتخاب کن، نام production را `edt-ir` بگذار و تنظیمات build را دست نزن —
   `wrangler.toml` خودش `main` را به `_worker.js` نشان می‌دهد.
4. داخل worker به **Settings -> Variables and Secrets** برو و این‌ها را اضافه کن:

   | متغیر | مقدار | توضیح |
   | --- | --- | --- |
   | `ADMIN` | رمز عبور شما | مخفی (secret)؛ بدون آن هیچ سرویسی کار نمی‌کند |
   | `KEY` | یک رشته‌ی تصادفی | مخفی؛ نحوه‌ی ساخت UUID را عوض می‌کند و لینک `/<KEY>` را فعال می‌کند |
   | `UUID` | یک UUID نسخه‌ی 4 واقعی | اختیاری؛ اگر ندهی از `ADMIN` و `KEY` ساخته می‌شود |
   | `PROXY_CONCURRENT_DIAL` | `3` | چند کاندیدات همزمان تست می‌شوند |
   | `PRELOAD_RACE_DIAL` | `1` | آدرس مقصد از قبل resolve و مسابقه داده می‌شود |

5. **Settings -> Bindings**: یک KV namespace با نام binding دقیقاً `KV` اضافه کن. بدون آن پنل
   مدیریت، لاگ رویدادها و استخر IPهای محلی غیرفعال می‌مانند.
6. اگر بعد از اولین build چیزی را عوض کردی، دوباره Deploy بزن.

اگر از نسخه‌ی قبلی `config.json` در KV داری، یک بار `/admin` را باز کن و دکمه‌ی **Reset defaults**
را بزن: کلیدهای ذخیره‌شده چینی بودند و worker حالا کلید انگلیسی می‌خواهد.

## تنظیمات پیشنهادی کلاینت برای ایران

نشانی `https://<your-worker>.workers.dev/admin` را باز کن، با مقدار `ADMIN` وارد شو و این‌ها را
تنظیم کن:

| فیلد | مقدار | دلیل |
| --- | --- | --- |
| Use ECH | روشن | تنها راه عملی برای پنهان کردن SNI از فیلتر روی `workers.dev` |
| ECH inner SNI | `cloudflare-ech.com` | نامی که با آن ECH جستجو می‌شود |
| ECH DoH resolver | `https://dns.alidns.com/dns-query` | از داخل ایران در دسترس است، برخلاف Google DoH |
| ClientHello fragmentation | `Shadowrocket` یا `Happ` | دست‌دهی TLS را تکه‌تکه می‌کند تا SNI خوانده نشود |
| Protocol / Transport | `vless` / `ws` | تست‌شده‌ترین مسیر |
| uTLS fingerprint | `chrome` | همانندسازی با handshake مرورگر واقعی |
| Refresh interval (hours) | `3` | آدرس‌های `workers.dev` زود به‌زود دسته‌بندی می‌شوند |
| Skip certificate verify | خاموش | لازم نیست؛ گواهی لبه معتبر است |

**Subscription URL** را از همان پنل کپی کن و در کلاینتت وارد کن. کلاینت‌های پشتیبانی‌کننده از
ECH: v2rayNG، Streisand، Happ، Shadowrocket، sing-box.

## استخر proxyIP عمومی

در ابتدای فایل `_worker.js` این لیست را پیدا می‌کنی:

```
const publicProxyPool = ['proxyip.cmliussss.net', 'fra.tp1.090227.xyz', 'sin.tp1.090227.xyz'];
```

این‌ها سرورهای اهدایی‌اند، زیرساخت تو نیستند؛ انتظار داشته باش عوض شوند. لیست را کوتاه نگه دار:
هر دامنه‌ی اضافه یک جستجوی DNS-over-HTTPS بیشتر برای هر اتصال هزینه دارد. اگر سرور خودت را داری،
متغیر `PROXYIP` را با لیست جداشده با کاما پر کن — تنها راه مطمئن همین است.

## عیب‌یابی

1. از همان دستگاه و همان شبکه آدرس `https://speed.cloudflare.com/__down?bytes=10` را باز کن. اگر
   آن هم نشد، مشکل فیلتر بودن `workers.dev` توسط اپراتور است، نه worker. با اینترنت موبایل یا DNS
   دیگر امتحان کن.
2. اگر ریشه‌ی آدرس worker صفحه‌ای داد که «No admin password configured»، یعنی کد درست دیپلوی شده
   است.
3. اگر `/admin` بعد از رمز درست دوباره به `/login` برگشت، یعنی User-Agent بین دو درخواست عوض شده
   است (کوکی به آن گره خورده).
4. اگر سابسکریپشن اضافه می‌شود ولی هیچ‌وقت وصل نمی‌شود: در پنل بررسی کن فیلد egress خالی نباشد،
   `PROXY_CONCURRENT_DIAL` را روی `4` بگذار و یک نود دیگر را تست کن.
5. پلن رایگان روزی ۱۰۰٬۰۰۰ درخواست به کل worker می‌دهد و هر اتصال پروکسی یکی از آن‌هاست؛ در یک
   خانه‌ی پرجمعیت تا ظهر تمام می‌شود.

## توسعه

```
node --check _worker.js     # تک‌فایل ES module است، بدون build
```

Workflow به نام **Verify** در هر پوش همین چک را می‌زند، هر کاراکتر چینی در فایل‌های ریپو را رد
می‌کند، و اگر worker دوباره به صفحه‌ی تنظیمات بیرونی وابسته شود build را شکست می‌دهد.
