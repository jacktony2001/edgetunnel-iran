# edt-ir - ورکر کلادفلر تنظیم‌شده برای ایران

یک فایل `_worker.js`، بدون مراحل بیلد. اتصال VLESS / Trojan / Shadowsocks را در لبه‌ی کلادفلر
تمام می‌کند و ترافیک را از طریق یک relay (proxyIP) به بیرون می‌فرستد. پیش‌فرض‌هایش بر پایه‌ی
اندازه‌گیری روی یک خط واقعی ایران انتخاب شده‌اند، نه بر پایه‌ی مستندات آپ‌استریم.

* بدون سرور میانی، بدون دامنه، بدون هزینه: روی پلن رایگان کلادفلر و آدرس `*.workers.dev`.
* لازم: یک حساب کلادفلر و یک حساب گیت‌هاب.
* کل ریپو انگلیسی است و CI در صورت دیدن هر کاراکتر چینی در فایل‌های تحت ترک، build را رد می‌کند.

مجوز GNU GPL-2.0، به فایل `LICENSE` مراجعه کنید.

## اندازه‌گیری روی خط ایران (2026-09-20، بدون پروکسی، `curl` 8.19 ویندوز)

| آزمون | نتیجه | معنا |
| --- | --- | --- |
| `https://<worker>.halmsal.workers.dev/` | HTTP 200 در ۰.۳۷ ثانیه از `188.114.99.0` | ورکر، نامش و IP آن از ایران بدون هیچ پروکسی در دسترس‌اند |
| نام‌های زیر `*.workers.dev` که ورکر ندارند | بدون پاسخ DNS | این NXDOMAIN عادی است، فیلترینگ نه |
| SNI = `www.cloudflare.com` با `Host: <worker>.workers.dev` | **HTTP 403**، ۱۵۱ بایت، مستقیم از لبه | کلادفلر مسیردهی `workers.dev` را با SNI ناهماهنگ رد می‌کند، پس **fronting روی نام رایگان شدنی نیست** |
| `https://speed.cloudflare.com`، `github.com`، `www.google.com` | HTTP 200 | خط سالم است |
| `dns.alidns.com/dns-query` | وسط TLS قطع می‌شود | دست‌کاری می‌شود، نه فقط مسدود |
| `cloudflare-dns.com`، `dns.google` | connection reset | DoH مسدود است |
| `mozilla.cloudflare-dns.com`، `quad9`، `dns.sb`، `opendns` | پاسخ نمی‌دهند | DoH مسدود است |
| `a.pages.dev`، `c.eu.org` | آدرس خصوصی `10.10.34.x` برمی‌گردد | ریزالور برای این zoneها جواب می‌سازد، پس دامنه‌رایگان‌های آن‌جا قابل‌اعتماد نیستند |
| `proxyip.cmliussss.net`، `fra./sin.tp1.090227.xyz` | TLS قطع شد | رله‌های اهداییِ خروجی مرده‌اند |
| `https://speed.cloudflare.com/__down?bytes=10` | HTTP 200 | آزمون معیار: اگر این نشود، مشکل از ISP است |

**پس چه چیزی واقعاً خراب است؟** نه DNS و نه SNI - روی این خط ورکر ساده در دسترس است. حلقه‌ی
مرده **پرش خروجی** است: ورکر تونل را می‌پذیرد ولی باید بایت‌ها را به کسی بدهد، و آدرس‌های عمومی
اهدایی proxyIP دیگر handshake را کامل نمی‌کنند. به همین دلیل نود وصل می‌شود، کلاینت راضی است،
ولی هیچ‌چیز بارگذاری نمی‌شود.

## این بیلد چه می‌کند

| بخش | رفتار |
| --- | --- |
| آدرس نود | یک IPv4 واقعی کلادفلر روی **443**؛ پورت‌های غیراستاندارد کلادفلر روی خط ایران بی‌اعتمادند، پس چیزی تصادفی نمی‌شود |
| `sni` و `host` نود | هر دو همان هوست‌نیم `*.workers.dev` - اجباری، به اندازه‌گیری 403 بالا نگاه کن |
| egress بدون `PROXYIP` | مقدار پیش‌فرضِ colo به‌علاوه‌ی `publicProxyPool`، قاطی و مسابقه‌ای؛ fallback مستقیم روشن |
| egress با `PROXYIP` | کل لیست شما dedup، قاطی و مسابقه‌ای؛ طبق خواسته fallback خاموش |
| خروجی سابسکریپشن | برای هر نوع کلاینت محلی تولید می‌شود؛ چون APIهای مبدل عمومی مرده‌اند، به‌صورت پیش‌فرض هیچ سرویس بیرونی صدا زده نمی‌شود |
| تشخیص | `/admin/pool` هر نامزد egress و resolver مربوط به ECH را **از لبه** تست می‌کند و JSON با وضعیت و میلی‌ثانیه می‌دهد |
| پنل ادمین | داخل خود ورکر سرو می‌شود (`/login` و `/admin`)؛ هیچ چیز از صفحه‌ی شخص ثالث بارگذاری نمی‌شود |
| زبان | نام متغیرها، کامنت‌ها، رشته‌ها و کلیدهای config همگی انگلیسی |

## دیپلوی

1. این ریپو روی حساب گیت‌هاب شماست.
2. داشبورد کلادفلر -> **Workers & Pages** -> **Create** -> **Deploy from Git**. اگر اتصال گیت‌هاب
   نیست، از **Settings -> Git integration** سطح حساب اضافه کنید و فقط دسترسی همین ریپو را بدهید.
3. همین ریپو را انتخاب کنید. کلادفلر نام ورکر را از نام ریپو می‌سازد، پس آدرس اینجا
   `edgetunnel-iran.halmsal.workers.dev` است؛ بقیه پیش‌فرض - `wrangler.toml` مقدار `main` را به
   `_worker.js` نشان می‌دهد.
4. ورکر -> **Settings -> Variables and Secrets**:

   | متغیر | مقدار | توضیح |
   | --- | --- | --- |
   | `ADMIN` | رمز شما | secret؛ بدون آن هیچ سرویسی بالا نمی‌آید |
   | `KEY` | یک رشته‌ی تصادفی | secret؛ در ساخت UUID اثر دارد و لینک سریع `/<KEY>` را فعال می‌کند |
   | `UUID` | یک UUID نسخه‌ی ۴ | اختیاری؛ اگر نگذاریدش، از `ADMIN` و `KEY` ساخته می‌شود |
   | `PROXY_CONCURRENT_DIAL` | `3` | چند نامزد egress هم‌زمان dial می‌شود |
   | `PRELOAD_RACE_DIAL` | `1` | آدرس مقصد از قبل resolve و مسابقه داده می‌شود |
   | `URL` | معمولاً **پاکش کنید** | `URL=1101` باعث می‌شود صفحه‌ی ریشه یک «Worker threw exception» جعلی چاپ کند؛ آن خطا واقعی نیست |
   | `SNI` | خالی بگذارید | فقط با دامنه‌ی شخصی معنا دارد، به اندازه‌گیری بالا نگاه کنید |
   | `CFPORT` | اختیاری | پورت نود، پیش‌فرض `443` |

5. **Settings -> Bindings**: یک KV namespace با binding name برابر `KV` اضافه کنید. بدون آن پنل،
   لاگ رویدادها و استخر IP محلی از کار می‌افتد.
6. هر کامیت روی `main` خودش خودکار دیپلوی می‌شود.

اگر از بیلد قدیمی `config.json` در KV مانده، یک بار `/admin` را باز کنید و **Reset defaults** را
بزنید - کلیدهای قدیمی چینی بودند و الان نادیده گرفته می‌شوند.

## تنظیماتی که باید بگذارید

نشانی `https://<your-worker>.workers.dev/admin` را باز کنید، با مقدار `ADMIN` وارد شوید:

| فیلد | مقدار | چرا |
| --- | --- | --- |
| Outer SNI | **خالی** | کلادفلر SNI ناهماهنگ را روی `workers.dev` رد می‌کند (اندازه‌گیری بالا) |
| Protocol / Transport | `vless` / `ws` | مطمئن‌ترین مسیر روی `workers.dev` |
| uTLS fingerprint | `chrome` | مثل دست‌دهی مرورگر واقعی |
| ClientHello fragmentation | `Shadowrocket` یا `Happ` | handshake را تکه‌تکه می‌کند؛ روی خط پرنویز MCI/Irancell اثر دارد، هرچند DPI می‌تواند دوباره جمعش کند |
| Node port | `443` | بقیه‌ی پورت‌های کلادفلر روی خط ایران بی‌اعتمادند |
| Refresh interval (hours) | `3` | رنج‌ها و رله‌ها مدام عوض می‌شوند |
| Use ECH | **خاموش** | توضیحش پایین‌تر آمده |
| Skip certificate verify | خاموش | لبه همین حالا گواهی معتبر می‌فرستد |

**در مورد ECH صادق باشیم.** کلید `ECH` فقط یک راهنمای `&ech=<inner SNI>+<DoH URL>` به انتهای لینک
اضافه می‌کند. تا وقتی DoH قابل‌دسترسی نباشد که `ECHConfigList` واقعی بگیرد، هیچ handshake با ECH
انجام نمی‌شود و SNI بیرونی همان‌طور روشن می‌ماند - و همه‌ی resolverهایی که این پروژه قبلاً پیشنهاد
می‌کرد روی این خط مسدود یا دست‌کاری‌شده‌اند (جدول بالا). خاموشش بگذارید. ECH واقعی شدنی است اگر
`ECHConfigList` را از پیش داخل کلاینت بگذارید (sing-box با `tls.ech`، بدون نیاز به DoH) و تنها راه
رایگانِ پنهان‌کردن نام `workers.dev` وقتی SNI فیلتر شدنیش سخت‌تر شود همان است؛ ولی این تنظیم
کلاینت است، نه چیزی که ورکر بتواند از طرف شما جعل کند.

## ترافیک از کجا بیرون می‌رود

تونل تا کلادفلر درست کار می‌کند؛ حلقه‌ی غایب جایی است که کلادفلر بایت‌ها را تحویل می‌دهد.

1. اول نگاه کنید: وقتی وارد شده‌اید `https://<your-worker>.workers.dev/admin/pool` را باز کنید. هر
   نامزد egress از لبه dial می‌شود و `reachable`، وضعیت HTTP و میلی‌ثانیه را می‌نویسد.
2. اگر هیچ‌کدام reachable نبود، هیچ تنظیم کلاینتی نجات نمی‌دهد؛ خروجی لازم دارید. به ترتیب ارزان‌تر:
   یک proxyIP اهدایی که **الان** زنده است (هاستش را در `PROXYIP` بگذارید)، VPS یک آشنا با SOCKS/HTTP،
   یا یک دستگاه free-tier خودت که relay اجرا کند.
3. `publicProxyPool` را کوتاه نگه دار (بالای `_worker.js`): هر هاست اضافه یک lookup DNS به هر dial
   اضافه می‌کند و عضو مرده فقط مسابقه را کند می‌کند.

## عیب‌یابی

1. «Error 1101: Worker threw exception» روی صفحه‌ی ریشه: با `URL=1101` این صفحه‌ی تظاهرِ خودِ همین
   ورکر است و عمداً چاپ می‌شود. متغیر `URL` را پاک کن تا صفحه‌ی واقعی برگردد.
2. نود وصل می‌شود ولی چیزی بارگذاری نمی‌شود: `/admin/pool`، همان‌طور که بالا آمد.
3. `/admin` بعد از رمز درست به `/login` برمی‌گردد: user agent بین دو درخواست عوض شده، چون کوکی به
   آن گره خورده است.
4. پنل باز می‌شود ولی فیلدها غلط یا خالی‌اند: یا KV با نام `KV` بسته نشده، یا `config.json` قدیمیِ
   چینی در KV مانده - **Reset defaults** را بزن.
5. پلن رایگان روزی ۱۰۰٬۰۰۰ درخواست برای کل ورکر دارد و هر اتصال پروکسی یک درخواست است؛ یک خانه‌ی
   پرمصرف تا ظهر تمامش می‌کند.

## توسعه

```
node --check _worker.js     # یک ES module تکی، بدون بیلد
```

workflow **Verify** در گیت‌هاب همین چک را روی هر push می‌گیرد، کاراکتر چینی را رد می‌کند، و اگر
ورکر دوباره به صفحه‌ی ادمین بیرونی وابسته شود build را می‌شکند.
